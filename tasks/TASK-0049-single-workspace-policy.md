## Incident log

Eval Lab accumulated many task-specific Git worktrees across `D:\claude` and
under the repository, plus five separate `.venv` directories (the main checkout
and TASK-0002, TASK-0003, TASK-0004, and TASK-0006). All five environments were
reported as Python 3.12.10; package contents and disk use have not yet been
compared. No root-level `node_modules` was found in Eval Lab or Design Bakery in
the reported shallow check. Root-level `node_modules` exists in nearby InferHub
and inference-recommendation-engine projects, but redundancy there is unverified
and is outside this task's cleanup scope.

The GitHub `project-continuity-modules` guidance inspected for this incident
does not prescribe sibling worktrees or per-task environments. Eval Lab's own
`AGENTS.md` did: it recommended `../eval-lab-TASK-0001` for each task. A later
checkpoint documented consolidation under `.worktrees`, but the canonical
instruction was not updated. Thus worktree proliferation was directly enabled
by stale repository policy. GitHub stores pushed commits and branches; it does
not store or clean up the local worktree directories.

## Objective

Make `D:\claude\eval-lab` the sole local checkout for Eval Lab, prohibit
additional clones and Git worktrees for routine task work, and use one root
`.venv` managed by `uv` with the root lockfile. Keep task history durable in
GitHub through validated, checkpointed commits and pushes. Audit existing
directories before removing anything; preserve unpushed commits, untracked
files, experiment artifacts, and the existing TASK-0048 handoff.

## Decisions

- The user's existing `D:\claude\eval-lab` folder is the canonical working
  directory. Work proceeds sequentially in this checkout; task branches may be
  switched here only after committing and pushing a checkpoint.
- Do not create any new clone, worktree, task-specific `.venv`, or
  task-specific `node_modules`.
- Use the single root `.venv` via `uv sync` when the locked dependencies need
  synchronization. Do not silently share an incompatible mutable environment;
  serialize work and sync the one canonical environment. No duplicate
  environment is an approved default.
- Commit and push each validated coherent checkpoint, and do not leave completed
  task state only on the local machine. Never push credentials or private data.
- Existing extra directories are not deleted until their tracked changes,
  untracked/ignored files, and unpushed commits have been inventoried and safely
  preserved or explicitly classified as disposable.
- User subsequently expanded the cleanup audit to all project folders under
  `D:\claude`. Four additional Hades checkouts share the same commit; three
  contain the same 1,822 staged deletions, and several contain conflicting
  untracked files. Their unique state is being cataloged before removal.
  Additional linked worktrees were found under `D:\claude\worktrees` and
  nested project folders.
